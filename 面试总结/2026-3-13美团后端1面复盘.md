### **【Q2】ArrayList 和 LinkedList 的区别？**
高分回答（示例）：
底层结构上，ArrayList 基于动态数组，LinkedList 基于双向链表。  
复杂度上，ArrayList 随机访问是 O(1)，中间插入/删除通常 O(n)；LinkedList 定位节点 O(n)，但在已定位节点处插入删除 O(1)。  
工程上，ArrayList 更符合 CPU 缓存局部性，综合性能通常更好，LinkedList 只有在“频繁头尾插删且很少随机访问”的场景才可能占优。  
结合项目，“雅鉴生活志”里高频数据更多在 Redis/DB，不在 JVM 内存链表上做复杂结构操作，所以集合选择通常优先 ArrayList。

### **【Q5】什么情况下会触发类初始化？**
高分回答（示例）：
主动使用会触发，常见包括：  
1) `new` 创建对象；  
2) 访问或赋值该类的静态变量（非 `final` 编译期常量）；  
3) 调用该类静态方法；  
4) 反射主动使用；  
5) 初始化子类前先初始化父类；  
6) 启动类（含 `main`）初始化。  
不会触发的典型场景：访问编译期常量、创建“该类数组类型”。

### **【Q6】在另一个类里调用某个静态字段，会触发该类初始化吗？**

### **【Q8】Java 里怎么创建线程？**

### **【Q12】`synchronized` 和 `ReentrantLock` 的区别？**
高分回答（示例）：
`synchronized` 是 JVM 内置监视器锁，语法简单，自动释放；  
`ReentrantLock` 是 JUC 显式锁，支持可中断、公平锁、尝试加锁、条件队列，多条件变量更灵活。  
结合项目，订单链路最终使用了 Redisson 分布式锁，不是单机锁；因为秒杀是多实例场景，`synchronized` 仅在单 JVM 有效。

### **【Q13】你项目里用到锁了吗？**
高分回答（示例）：
用了分布式锁。

### **【Q14】给表建索引要考虑哪些因素？**
高分回答（示例）：
从“收益-成本-稳定性”三维回答：  
1) 查询模式：where/join/order by/group by 高频列；  
2) 选择性（区分度）：高区分列优先；  
3) 联合索引列顺序：最左前缀、等值优先、范围靠后；  
4) 覆盖索引机会；  
5) 写放大成本（插入/更新维护索引）；  
6) 数据量与冷热分布。  
结合实习经历可补一句：通过慢 SQL 反推索引，而不是先拍脑袋建索引。

### **【Q15】建了索引查询仍然慢，怎么排查？**
高分回答（示例）：
我的排查步骤是：  
1) 先看慢查询日志定位 SQL；  
2) `EXPLAIN` 看 `type/key/rows/Extra`，判断是否走索引、是否回表/临时表/文件排序；

### **【Q18】你用消息队列做了哪些事情？**
高分回答（结合当前项目实际）：
在“雅鉴生活志”这个代码版本里，异步链路是 **Redis Stream**，不是 RabbitMQ：  
用户请求进入后先执行 Lua 完成资格校验与预扣库存，再 `XADD` 到 `stream.orders`；后台单线程消费者 `XREADGROUP` 拉取并创建订单，成功后 `XACK`。

高分回答（示例）：
核心价值是三点：解耦、削峰、异步。  
在秒杀场景下，异步化最直接：前台快速给用户反馈，后台平滑消费，防止数据库被瞬时流量打穿。

高分回答（示例）：
主要体现“异步 + 削峰”。  
在峰值流量时，请求线程不做完整下单事务，只做轻量校验后入流；真正的落库由消费者按能力处理。

### **【Q21】为什么要异步？主线程是做什么的？请举场景。**
高分回答（示例）：
异步的本质是把“用户强感知路径”和“可延后任务”拆开。  
主线程应优先完成高优先级动作（参数校验、资格判断、快速响应）；耗时任务（如下单落库、通知）交给异步通道。

### **【Q23】订单号怎么生成？在发送端还是消费端生成？**

### **【Q26】讲一下 Cache Aside 模式。**
高分回答（结合项目）：

### **【Q27】为什么更新数据库后删缓存，而不是直接更新缓存？**
高分回答（示例）：
删缓存优于改缓存有三个原因：  
1) 并发写时“改缓存”容易发生覆盖回退（新值被旧写覆盖）；  
2) 缓存字段可能比数据库复杂，更新路径容易漏字段；  
3) 热点不稳定时，删缓存让下一次读按需回源，整体更稳。  
结合项目：已经采用“先写库后删缓存”，并可进一步加延迟双删/消息补偿提升一致性上限。

### **【Q30】算法题：最长公共子序列（LCS）怎么做？动态规划思路？**
高分回答（示例）：
定义 `dp[i][j]`：`text1[0..i-1]` 与 `text2[0..j-1]` 的 LCS 长度。  
转移：  
- 若 `text1[i-1] == text2[j-1]`，`dp[i][j] = dp[i-1][j-1] + 1`；  
- 否则 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`。  
初始化第 0 行/列为 0，答案是 `dp[m][n]`，时间 O(mn)，空间 O(mn)（可压缩到 O(n)）。  
面试时要先给状态定义再给转移，这是关键得分点。

### B. 项目一致性层（真实性风险）
- 简历写 RabbitMQ，但代码是 Redis Stream，且追问时未快速校准口径。  
- 一旦出现“技术名词与实现不一致”，面试官会提高怀疑阈值。

### C. 分布式一致性层（核心短板）
- 面试官最重视的是：至少一次消费、重试、幂等、重复订单。  
- 你意识到了重试存在，但缺少“数据库唯一约束 + 幂等键 + ACK 策略”的完整方案。

### D. 算法表达层（方法论不足）
- LCS 没有先定义状态，导致后续无法推进。  
- 算法题不是“是否见过”，而是“能否结构化表达”。

## 3. 面试官追问链路复盘（你必须掌握）
- 链路是：消息队列用途 → 异步价值 → 主线程职责 → 下单一致性 → 消费重试 → 幂等。  
- 这是非常典型的交易系统考察路径。  
- 以后遇到同类题，必须主动给出：  
  “消息至少一次投递” + “消费幂等设计” + “唯一约束兜底” + “异常补偿机制”。

## 4. 你的优势（要保留并放大）
- 有真实项目上下文，不是纯八股；  
- 对缓存、索引、异步这些方向有实践基础；  
- 面对追问态度稳定，沟通礼貌，具备可培养性。

## 四、结合当前代码可立即实施的技术改进（可作为二面加分项）

1) 为 `tb_voucher_order` 增加唯一索引（如 `user_id + voucher_id`）保证硬幂等；
