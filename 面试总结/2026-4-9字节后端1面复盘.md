### 7. 索引是什么？它是怎么实现的？

高分回答：

索引本质上是帮助数据库快速定位数据的数据结构，目标是减少扫描的数据量，提高查询效率。

在 MySQL 的 `InnoDB` 里，最常见的索引结构是 `B+` 树。之所以用 `B+` 树，是因为它是多路平衡搜索树，树高低、磁盘 IO 次数少，而且天然支持范围查询和排序。

如果再往下分，`InnoDB` 里常见有两类索引：

1. 聚簇索引，也就是主键索引，叶子节点存的是整行数据
2. 二级索引，叶子节点存的是索引列值和主键值

所以通过二级索引查询时，如果查询列不在索引里，往往还要再根据主键去聚簇索引里取完整数据，这就是后面常说的回表。

---

### 8. B+ 树在查询的时候是怎么找数据的？

高分回答：

可以把 `B+` 树查询理解成“从根节点一路向下做范围缩小”。

具体过程是：

1. 先从根节点开始，拿待查的 key 和当前节点里的多个 key 做比较
2. 根据比较结果决定走哪一个子指针
3. 进入下一层非叶子节点后，继续重复这个过程
4. 最后走到叶子节点，在叶子节点里找到对应记录

如果是聚簇索引，叶子节点里就是整行数据，找到后就能直接返回。

如果是二级索引，叶子节点里一般是主键值，所以拿到主键后，可能还要再去聚簇索引树里查一次完整记录。

如果查的是范围，比如 `between`、`>`、`<`，那定位到起始叶子节点之后，还可以利用叶子节点之间的有序链表继续顺序扫描，所以 `B+` 树特别适合范围查询。

---

### 9. 什么是回表？

高分回答：

回表通常发生在使用二级索引查询时。

因为二级索引的叶子节点里通常不存整行数据，只存索引列和主键值。如果 SQL 需要的字段在这个二级索引里拿不全，那么 MySQL 就得先通过二级索引找到主键，再回到聚簇索引里把完整行取出来，这个过程就叫回表。

比如索引只有 `(name)`，但你查的是：

```sql
select age from user where name = 'Tom';
```

这时通过 `name` 索引只能拿到主键，拿不到 `age`，所以还得再查一次主键索引。

如果查询需要的字段都已经包含在索引里，就可以避免回表，这种情况叫覆盖索引。

---

### 10. 什么是联合索引？

联合索引就是把**多个列**按**既定顺序**放到同一棵 `B+` 树里。

比如建一个 `(a, b, c, d)` 联合索引，它的有序性不是四列彼此独立，而是先按 `a` 排，再在 `a` 相同的范围内按 `b` 排，再按 `c`、`d` 排。

所以联合索引最核心的点不是“多个字段一起建索引”，而是“顺序很重要”。这也是最左匹配原则的来源。

---

### 11. 有一张表，`id` 是主键，`a b c d` 建了联合索引。`select a, b from table where a = 1 and b = 2 and c > 3 and d = 4` 这个查询用到了哪些列的索引？

高分回答：

如果从“索引定位范围”的角度回答，这条 SQL 主要用到了 `a`、`b`、`c`。

原因是联合索引 `(a, b, c, d)` 会先按最左匹配去定位：

1. `a = 1` 可以继续缩小范围
2. `b = 2` 也可以继续缩小范围
3. 到 `c > 3` 时变成范围查询，索引在这里就只能确定一个扫描区间
4. 后面的 `d = 4` 不能再继续用于“缩小索引扫描范围”

所以面试里标准回答一般是：真正用于定位的列是 `a`、`b`、`c`。

不过如果继续深挖，我会补一句：在一些版本和执行计划下，`d = 4` 可能通过索引下推参与过滤，但它不能像 `a b c` 那样继续参与有序定位。

---

### 12. 为什么没有用到 `d`？

高分回答：

因为在联合索引里，一旦前面的列出现范围查询，后面的列就不能继续用于有序定位了。

这里 `(a, b, c, d)` 中，`a` 和 `b` 都是等值匹配，走得很好；但到 `c > 3` 时，MySQL 只能先定位到 `a = 1 and b = 2` 这一段，再从 `c > 3` 的起点往后扫。既然已经进入“范围扫描”，那 `d = 4` 就不能再帮它进一步确定更精确的起止边界。

一句话总结就是：联合索引里，范围条件右边的列通常不能继续用于索引定位。

如果你想把答案再答高级一点，可以补一句：`d` 不参与范围定位，但可能参与索引下推过滤。

### 13. MySQL 里的 `binlog`、`redo log`、`undo log` 分别是做什么的？

高分回答：

这三个日志分别解决的是不同层面的问题：

1. `redo log`：`InnoDB` 引擎层的物理日志，核心作用是崩溃恢复。数据库宕机后，可以通过 `redo log` 把已经提交但还没来得及刷盘的数据恢复出来。它本质上依赖的是 `WAL`，也就是先写日志，再落数据页。
2. `undo log`：也是 `InnoDB` 层的日志，主要用于事务回滚，同时也支撑 `MVCC` 的版本链读取。
3. `binlog`：Server 层的逻辑日志，记录的是对数据造成变更的逻辑操作，主要用于主从复制和数据恢复。

如果面试官继续问三者关系，我会再补一句：

1. `redo log` 保证已提交事务尽量不丢
2. `undo log` 保证事务可回滚、快照读可见
3. `binlog` 负责复制和归档

### 14. 给你一个长度为 `n` 的单链表，要求从尾部每 `k` 个进行翻转，空间复杂度 `O(1)`，你怎么做？

高分回答：

这道题最关键的不是马上写反转，而是先做等价转化。

“从尾部每 `k` 个翻转”其实等价于：

1. 先统计链表长度 `n`
2. 计算 `r = n % k`
3. 头部前 `r` 个节点保持不动
4. 后面的节点按正常的每 `k` 个一组翻转

比如 `1 2 3 4 5 6 7`，`k = 3`，因为 `7 % 3 = 1`，所以前 `1` 个不动，后面按 `3` 个一组翻转，结果就是 `1 | 2 3 4 | 5 6 7` 变成 `1 4 3 2 7 6 5`。

算法步骤可以这样讲：

1. 第一次遍历统计长度 `n`
2. 用虚拟头节点 `dummy` 指向头结点
3. 让指针先走过前 `r = n % k` 个不用翻转的节点
4. 后面每次检查是否还有完整的 `k` 个节点
5. 如果有，就原地反转这一组，再和前后链表重新拼接

复杂度：

1. 时间复杂度 `O(n)`
2. 额外空间复杂度 `O(1)`

如果现场需要代码，我会写成下面这样：

```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

public ListNode reverseFromTailEveryK(ListNode head, int k) {
    if (head == null || head.next == null || k <= 1) {
        return head;
    }

    int n = 0;
    for (ListNode p = head; p != null; p = p.next) {
        n++;
    }

    int remain = n % k;
    ListNode dummy = new ListNode(0);
    dummy.next = head;

    ListNode pre = dummy;
    for (int i = 0; i < remain; i++) {
        pre = pre.next;
    }

    while (true) {
        ListNode groupTail = pre;
        for (int i = 0; i < k && groupTail != null; i++) {
            groupTail = groupTail.next;
        }
        if (groupTail == null) {
            break;
        }

        ListNode groupHead = pre.next;
        ListNode nextGroupHead = groupTail.next;

        ListNode prev = nextGroupHead;
        ListNode cur = groupHead;
        while (cur != nextGroupHead) {
            ListNode next = cur.next;
            cur.next = prev;
            prev = cur;
            cur = next;
        }

        pre.next = groupTail;
        pre = groupHead;
    }

    return dummy.next;
}
```

这题你当时最大的问题不是不会反转链表，而是没有把题目先转成自己熟悉的 `reverseKGroup` 模型。

### 17. 判断一个链表是不是回文链表

高分回答：

这道题的标准解法是：

1. 用快慢指针找到链表中点
2. 原地反转后半段链表
3. 从头结点和后半段新头同时往后比较
4. 如果都相等就是回文，否则不是
5. 如果想写得更完整，最后再把后半段恢复回来

这里快慢指针我会这样处理：

1. `fast` 一次走两步，`slow` 一次走一步
2. 当循环结束时，`slow` 停在前半段的尾部
3. 对于奇数长度，`slow.next` 正好是后半段起点
4. 对于偶数长度，`slow.next` 也是右半段起点

然后反转 `slow.next` 开始的链表，再用两个指针比较即可。

如果现场写代码，我会写成下面这样：

```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

public boolean isPalindrome(ListNode head) {
    if (head == null || head.next == null) {
        return true;
    }

    ListNode slow = head;
    ListNode fast = head;
    while (fast.next != null && fast.next.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }

    ListNode secondHead = reverse(slow.next);
    ListNode p1 = head;
    ListNode p2 = secondHead;
    boolean ok = true;

    while (p2 != null) {
        if (p1.val != p2.val) {
            ok = false;
            break;
        }
        p1 = p1.next;
        p2 = p2.next;
    }

    slow.next = reverse(secondHead);
    return ok;
}

private ListNode reverse(ListNode head) {
    ListNode prev = null;
    ListNode cur = head;
    while (cur != null) {
        ListNode next = cur.next;
        cur.next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}
```

这道题高分点有两个：

1. 说清楚奇偶长度时中点在哪里
2. 主动补一句“如果业务要求不破坏原链表，我会把后半段再恢复回去”

### 18. 你这边有什么问题想问我的吗？

高分回答：

我一般不会只问“组里做什么”，而是尽量问出岗位真实情况。可以这样问：

1. 我想了解一下，如果进入咱们组，实习生前一两个月通常会先接什么类型的任务？是偏线上问题、技术优化，还是会直接参与业务需求？
2. 组里评价实习生成长比较快，一般会看哪些能力？比如是代码质量、业务理解、推进能力，还是独立负责模块的能力？
3. 如果后面有机会继续深入，咱们组这边比较核心的技术挑战主要集中在哪些方向？

这种反问比“加班多不多”“什么时候有结果”更职业，也更容易让面试官觉得你是认真在看岗位匹配度。

## 三、这场面试最该补的点

### 1. 项目题要更像“讲方案”，不要只像“讲经历”

你其实做过事，但讲的时候容易变成平铺直叙。以后任何项目题都尽量套这个结构：

1. 背景是什么
2. 你的职责是什么
3. 核心链路怎么走
4. 难点在哪里
5. 结果和收益是什么

只要按这个框架讲，项目题就会明显更稳。

### 2. MySQL 基础要从“背概念”升级到“能展开”

这场 MySQL 题不算很难，但面试官明显在看你能不能把一层概念继续往下讲。你要重点补下面这些：

1. 聚簇索引和二级索引区别
2. 回表和覆盖索引
3. 联合索引、最左匹配、范围查询截断
4. 索引下推
5. `redo log / undo log / binlog` 的职责边界

### 3. 链表题要练“题目转化能力”

第一题其实不是冷门技巧题，而是“先转化，再套模板”。后面练题时重点做这几道：

1. `reverseKGroup`
2. 回文链表
3. 反转链表 II
4. 两两交换链表节点
5. 链表排序

## 四、下次面试前建议你直接背熟的回答

1. 一个 1 分钟自我介绍
2. 一个 2 分钟项目深挖回答
3. 索引、回表、联合索引、三大日志四个 MySQL 高频题

如果这四组内容你能讲顺，类似的一面通过率会明显高很多。
